# Звіт з лабораторної роботи: Безпека в IoT (MQTT)

**Тема:** Захист MQTT-брокера: анонімний доступ, автентифікація, TLS

---

## Завдання 1: Незахищене MQTT-з'єднання

### Виконані кроки
1. Запущено Mosquitto без автентифікації (`allow_anonymous true`) на порту 1883.
2. Підписано на топік `#` (усі топіки).
3. Надіслано фальшиві дані сенсора.
4. Надіслано команди на вимкнення пристроїв.

### Результати перехоплення

| Топік                        | Повідомлення                                      | Коментар                  |
|------------------------------|---------------------------------------------------|---------------------------|
| home/sensors/temperature     | `{"device":"sensor01","temp":99.9,"status":"FAKE"}` | Фальшива температура     |
| home/sensors/humidity        | `{"device":"sensor01","humidity":5,"status":"FAKE"}` | Фальшива вологість       |
| home/actuators/lamp/set      | `{"command":"OFF","source":"attacker"}`           | Команда вимкнення лампи  |
| home/actuators/relay/set     | `{"command":"OFF","source":"attacker"}`           | Команда вимкнення реле   |

**Висновок:** Будь-хто в мережі може:
- Читати всі дані сенсорів
- Підробляти показання сенсорів
- Керувати виконавчими пристроями (вимкнути лампу, реле тощо)

## Завдання 2: Захист через автентифікацію

### Користувачі
| Користувач  | Пароль           | Роль                  |
|-------------|------------------|-----------------------|
| admin       | AdminPass123     | Адміністратор         |
| sensor      | SensorPass456    | Сенсорний пристрій    |
| actuator    | ActuatorPass789  | Виконавчий пристрій   |

### Результати тестів
- Підключення **без пароля** → `Connection Refused: not authorised`
- Підключення з **неправильним паролем** → `Connection Refused: not authorised`
- Підключення з **правильним паролем** (admin / sensor / actuator) → **SUCCESS**

Повідомлення від сенсора успішно опубліковано з автентифікацією.

---

## Завдання 3: TLS/SSL шифрування

### Сертифікати
- **CA:** IoT-CA (самопідписаний)
- **Серверний сертифікат:** CN=localhost, підписаний CA
- Порт: **8883**

### Результати
- Підключення **без TLS** на 8883 → `Protocol error` / відмова
- Підключення **з TLS + CA + пароль** → **SUCCESS**
- Підключення **без CA** (перевірка сертифіката) → помилка

Трафік зашифрований (неможливо прочитати payload у Wireshark без ключів).

## Завдання 4: Аналіз та висновки

### Порівняльна таблиця

| Критерій                  | Без захисту                  | Тільки паролі                  | Паролі + TLS                          |
|---------------------------|------------------------------|--------------------------------|---------------------------------------|
| **Захист даних**          | Немає (plaintext + anonymous)| Середній (auth, але plaintext) | Високий (auth + encryption)           |
| **Складність налаштування**| Дуже низька                  | Низька                         | Середня / висока (сертифікати)        |
| **Продуктивність**        | Найвища                      | Висока                         | Трохи нижча (overhead TLS)            |
| **Захист від підслуховування** | Немає                    | Немає                          | Є                                     |
| **Захист від підробки**   | Немає                        | Є (потрібен пароль)            | Є                                     |
| **Рекомендація**          | Тільки для тестів            | Внутрішня мережа (якщо довіряєте) | **Виробниче використання**            |

### Виявлені загрози в незахищеній IoT-системі

1. **Перехоплення даних** - усі повідомлення сенсорів доступні будь-кому в мережі.
2. **Підробка даних сенсорів** - можна надсилати фальшиві значення температури/вологості.
3. **Несанкціоноване керування** - можна вимикати/вмикати реле, лампи, замки тощо.
4. **Відсутність аудиту** - немає ідентифікації, хто саме надсилав повідомлення.
5. **Man-in-the-Middle** - легко перехоплювати та змінювати повідомлення.
6. **Replay-атаки** - можна повторно надсилати старі команди.

### Рекомендації для захисту реальних IoT-пристроїв у домашній мережі

1. **Завжди використовуйте автентифікацію** - `allow_anonymous false` + password_file або JWT.
2. **Увімкніть TLS** на порту 8883 (або mTLS для критичних пристроїв).
3. **Використовуйте ACL** (Access Control Lists) у Mosquitto - обмежуйте топіки для кожного користувача (сенсор не повинен публікувати в `actuators/#`).
4. **Сильні унікальні паролі** + регулярна ротація.
5. **Сегментація мережі** - IoT-пристрої в окремій VLAN / гостьовій мережі.
6. **Firewall** - забороніть доступ до MQTT-порту з інтернету (тільки локальна мережа + VPN).
7. **Оновлення прошивки** пристроїв та брокера.
8. **Моніторинг** - логування підключень, аномалій (наприклад, занадто часті повідомлення).
9. **Не використовуйте стандартні порти/паролі** у production.
10. Для домашнього використання розгляньте готові рішення: Home Assistant + MQTT з TLS, або хмарні брокери з аутентифікацією (HiveMQ Cloud, AWS IoT тощо).
